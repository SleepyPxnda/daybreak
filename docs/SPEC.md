## Refresh on return

When the tab or window becomes visible or gets focus again, daybreak re-reads everything the page and header show (timeline, day info, balance, todos, notes list, tasks, overview, settings), so blocks booked in another tab or on another device appear without a reload. Nothing is fetched while the tab stays in the background or focused, on first load, or within 2 seconds of the last refresh; there is no refresh indicator.

- If the server cannot be reached on return, nothing changes: the page keeps its data and day, shows no error, and tries again on the next return.
- The Today page (`/` without `?date=`) moves to the new day after midnight: "Heute", timeline, day setting, now-line and undated quick input (line on the page and `Strg+K`) follow it. With `?date=…` it stays on the chosen day; only the "Heute" button and label follow. The week page without `?week=` moves to the new current week.
- Unsaved input is kept: open dialogs, the command palette and the note editor are not touched. The "Arbeitszeit & Stundenkonto" form on `/settings` keeps typed values and takes values saved in another tab only while it has no unsaved changes. After "Speichern" it shows the stored (normalised) values.
- Not refreshed: the content of the open note, the todo archive, and values fixed when a component is set up (mini month today marker, default years, default start dates and ranges). The day changes only on return, not at midnight.

## Notes: kinds and task notes

Superseding the Markdown parts of [phase-3-notes.md](phase-3-notes.md): note content is plain text and is shown and saved exactly as typed. There is no preview and no rendering anywhere; Markdown characters stay as typed text.

- **Kind:** a note can have a kind: Meeting, Problem or Info. Notes without a kind (for example older notes) show none active. A kind can be changed but not removed again. It is a label only, with no status such as open or resolved. Each kind has one tint everywhere (Meeting blue, Problem red, Info green, never amber). In the `/notes` list and in "Heute → Notizen" the kind is a tinted icon only (its label is the accessible name and tooltip); the editor's kind control, the kind filter and the task page sections show icon and label.
- **Editor:** one meta row (kind dropdown, "Bezug" picker about 300px wide with the link "Zur Aufgabe" for a task and an × "Bezug entfernen", tags typed as `#redis #technik`, save status, pin, delete), then the large borderless title, then one borderless plain text field that grows with its content. There are no visible field labels; each control has its word as accessible name. The title wraps over several lines (Enter adds no line break). "Gespeichert" shows in subdued green. Autosave, `Strg+S`, pinning and deletion work as before. Switching quickly between notes always shows the note in the URL.
- **Pinning** does not change "last changed" and does not move the note in the list; changing title, content, tags, kind or link does. The editor's "Gespeichert · <Zeit>" shows the note's stored last change (`HH:mm` for today, `dd.MM. HH:mm` for earlier days), so pinning alone leaves it unchanged.
- **`/notes`:** the header has the search field, `+` and three filter buttons "Art", "Konto" and "Tag" (no tag cloud). "Art" is "Alle · Meetings · Probleme · Infos"; "Konto" lists "Alle" and the active accounts and shows every note whose "Bezug" is that account or any of its tasks (open or closed; a task note belongs to the task's current account); "Tag" is a searchable list of tags with counts, with a × next to it to clear. The filters are kept in the URL as `?kind=meeting|problem|info`, `?account=<id>` and `?tag=`, and combine with each other and with search. An archived account in the URL stays shown, marked "archiviert"; an unknown id shows "Konto" and no results. With filters active, `+` and "Neue Notiz" create a note of the chosen kind with the chosen account as "Bezug" (also an archived one); with an unknown account id the note is created without "Bezug" and no error shows. The list is grouped into "Angepinnt", "Heute", "Diese Woche" and one section per older month (newest first), by last change. A row has at most two lines: kind icon, title and date; then the task key chip (or the account dot) and the excerpt. Below the `lg` breakpoint the page shows either the list or, with `?id=`, the editor with "Zurück zur Liste"; `?tag=`, `?kind=` and `?account=` are kept, also on create and delete.
- **Task page `/tasks/[id]`:** the "Notizen" card shows the linked notes in sections "Probleme", "Infos", "Meetings", then "Ohne Art" (only when such notes exist), each with a count and a rail in the kind's colour. Each kind section has a create button that creates a note of that kind, linked to the task and titled with the task title. An empty kind section shows "Noch keine Probleme." / "Noch keine Infos." / "Noch keine Meetings." The page looks the same for closed tasks. A row shows title, date of last change and excerpt; clicking it opens the full text read-only in place (several rows can be open), with a link "Bearbeiten" to `/notes?id=<id>`. Order within a section: pinned first, then most recently changed.
- **Quick input:** `nm <Titel>`, `np <Titel>` and `ni <Titel>` create a meeting, problem or info note. If the first word after the prefix is exactly a task key, the note is linked to that task and the rest is the title (`np GB-114 Cache läuft voll`); without further words the task title is used. `n <Titel>` is unchanged: no kind, no key match. The preview line names the kind and the task.
- **Deleting a task** keeps its notes: they lose the task link and are linked to the task's account. The delete dialog says so.
- **References:** a note can point to other notes and tasks by typing plain text in double brackets: `[[#<id> <Text>]]` for a note (the link shows the note's current title) and `[[<task key>]]` for a task (key compared ignoring case and surrounding spaces). Typing `[[` opens the dialog "Verweis einfügen" (notes by title or content, open tasks with a key of active accounts) and inserts the token; the first listed result is highlighted, so Enter inserts it, and the highlight returns to it whenever the results change. Other text in double brackets does not resolve. The text itself is never linked or rendered; below it, "Verweist auf" lists the resolved references in order of first appearance, live while typing (a closed task or a task of an archived account shows muted; an unresolved one shows "nicht gefunden" and is not a link; the note itself is left out), and "Erwähnt in" lists other notes that reference this note. List excerpts show a note reference as its text and a task reference as the key. Nothing is stored for references; renaming or deleting the target is not rewritten in the text.
- **Mentions on the task page:** the "Notizen" card adds a last section "Erwähnt in" (count, neutral rail, kind icon before the title, no create button) with notes that reference the task's key without having the task as "Bezug". It is also shown for a closed task and never for a task without a key.
- **Long text:** long titles, task keys and account names never overflow or cause a horizontal scrollbar. One-line places cut the text off with a fade and show the full text as tooltip; the editor title wraps and breaks inside long words. A task key chip is at most 7.5rem wide and fades only when it is cut off. On `/notes`, a long tag on the "Tag" button (faded only when cut off), in the tag list and a long account name in the "Konto" list fade the same way and show the full text as tooltip. The "Tag" button announces a dialog popup (`aria-haspopup="dialog"`).

## Smaller interface rules

- **Day closing via link:** loading `/?dayClosing=1` directly (new tab, reload, the end-of-day notification) opens the "Tagesabschluss" sheet for today and the URL becomes `/`; a client-side navigation to it does the same.
- **Vacation card:** "genommen", "geplant" and "verfallen" show a value above 0 with a minus sign ("−4,5") and 0 as "0", never "−0". Handed-on entitlements with the same year of origin, label and start date all show, in the card and on `/settings#vacation`.
- **`/accounts` sorting:** releasing a dragged account in a gap between rows or in the list padding drops it at the dashed slot. After any drag ends (drop, Esc, release outside the list, an aborted drag) no row stays hidden and no slot stays visible. The grip of an active row is an image with the accessible name "Ziehen zum Sortieren"; sorting stays a mouse action.
